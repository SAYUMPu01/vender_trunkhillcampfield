# Trunkhill Campfield

ระบบจองลาน ห้องพัก และเช่าอุปกรณ์ด้วย Next.js และ MySQL/MariaDB

## เปิดบนเครื่อง

ต้องมี Node.js 22 ขึ้นไป, npm และ Docker Desktop

```powershell
npm ci
docker run --detach --name trunkhill-local-db --publish 127.0.0.1:33316:3306 --env MARIADB_RANDOM_ROOT_PASSWORD=1 --env MARIADB_DATABASE=trunkhill --env MARIADB_USER=trunkhill --env MARIADB_PASSWORD=local-trunkhill-db mariadb:11.4
Copy-Item .env.example .env.local
```

ถ้าคอนเทนเนอร์มีอยู่แล้วแต่หยุดอยู่ ใช้ `docker start trunkhill-local-db` แก้ `.env.local` ให้มี `ADMIN_PASSWORD` อย่างน้อย 12 ตัวอักษรและ `ADMIN_SESSION_SECRET` แบบสุ่มอย่างน้อย 32 ตัวอักษร ตัวอย่างคำสั่งสร้าง secret คือ `node -e "console.log(require('node:crypto').randomBytes(40).toString('hex'))"`

```powershell
npm run db:init
npm run dev -- --hostname 127.0.0.1
```

เปิด http://127.0.0.1:3000 และเข้าหน้าจัดการที่ http://127.0.0.1:3000/admin โดยใช้รหัสใน `.env.local`

ฐานข้อมูลเดิมให้รัน `npm run db:init -- --reschedule-only` ก่อนเปิดเว็บที่มีระบบเลื่อนวันเข้าพัก

ระบบเปิด–ปิดโซน: ฐานข้อมูลเดิมรัน `node --env-file=.env.local scripts/zone-status-schema.mjs` ก่อนอัปเดตเว็บ (โซนเดิมทั้งหมดเริ่มต้นเปิดใช้งาน) จัดการได้ที่ **ลานกางเต็นท์ → จัดการโซน** การปิดจะซ่อนล็อกของโซนจากหน้าจองและป้องกันการจองใหม่/เลื่อนเข้ามา โดยเก็บข้อมูลและรายการจองเดิมไว้ เมื่อเปิดใหม่ สถานะของแต่ละล็อกยังคงเดิม

เงื่อนไขปัจจุบัน: แอดมินกำหนดจำนวนครั้งได้ 0–255 ครั้ง และวันล่วงหน้าได้ 0–365 วัน ที่เมนู “เงื่อนไขการแก้ไขจอง” ค่าเริ่มต้น 3 ครั้ง / 3 วัน จำนวนครั้ง 0 คือปิดรับการเลื่อน การเปลี่ยนโควต้ามีผลกับการจองเดิมและใหม่ แต่ไม่ล้างจำนวนครั้งที่ใช้ไป วันล่วงหน้าใช้กับทั้งวันเข้าพักเดิมและวันเข้าพักใหม่ตามวันที่ประเทศไทย ค่า 0 วันอนุญาตให้เลื่อนได้ถึงวันเข้าพักเดิม ระบบตรวจค่าล่าสุดอีกครั้งก่อนบันทึก ฐานข้อมูลเดิมรัน `node --env-file=.env.local scripts/init-reschedule-limit.mjs` ทดสอบด้วย `node --env-file=.env.local scripts/test-booking-policy.mjs` และ `node --env-file=.env.local scripts/test-restricted-reschedule.mjs`

ฐานข้อมูลเดิมให้รัน `npm run db:init -- --pricing-only` ก่อนเปิดเว็บที่มีระบบปฏิทินและราคาตามวัน

## ป้องกันไฟล์สลิปซ้ำและบล็อกเบอร์โทร

ฐานข้อมูลเดิมรัน `node --env-file=.env.local scripts/init-slip-protection.mjs` ก่อนเปิดเวอร์ชันนี้ การติดตั้งใหม่ใช้ `npm run db:init` ได้ตามเดิม ระบบนำไฟล์ที่เคยอัปโหลดเข้าทะเบียนด้วย แต่ไม่ย้อนหลังยกเลิกการจองหรือนับโทษจากข้อมูลเดิม

- ยกเลิก OCR แล้ว ไม่มีการอ่านยอด ชื่อ วันที่ หรือบัญชีจากภาพ สลิปใหม่รอแอดมินตรวจเงินจริง
- ตรวจ SHA-256 ของไฟล์ทั้ง JPG/PNG/WebP/PDF ถ้าไฟล์เดียวกันเคยใช้กับการจองอื่น จะปฏิเสธและยกเลิกการจองใหม่ พร้อมคืนสต็อก การเปลี่ยนชื่อไฟล์ไม่ช่วยหลบการตรวจ แต่การแก้ภาพ/บันทึกไฟล์ใหม่อาจตรวจไม่พบ
- นับสลิปซ้ำครั้งเดียวต่อรายการจอง เบอร์เดิมสะสมเกิน 3 ครั้ง (ครั้งที่ 4) จะถูกบล็อก ไม่ให้จองใหม่หรือส่งสลิปในรายการที่ยังค้างอยู่ รองรับการรวมรูปแบบเบอร์ไทย 0 / +66 / 66 / 0066 เป็นเบอร์เดียวกัน
- ใช้ทะเบียนแฮชไม่ซ้ำและล็อกฐานข้อมูล ป้องกันสลิปเดียวกันผ่านพร้อมกันสองรายการ การกดส่งซ้ำรายการเดิมไม่นับโทษเพิ่ม
- แอดมินเปิด **เบอร์ที่ถูกบล็อก** เพื่อค้นหา ดูประวัติ และปลดล็อก การปลดล็อกเริ่มนับใหม่ เก็บประวัติเดิม และไม่คืนสถานะรายการที่ถูกยกเลิกหรืออนุญาตให้ใช้สลิปเก่าซ้ำ
- ทดสอบด้วย `node --env-file=.env.local scripts/test-slip-protection.mjs` กับ local พอร์ต 3001 สคริปต์สร้างและลบเฉพาะข้อมูลทดสอบ

ช่องทางโอนเลขบัญชี: ฐานข้อมูลเดิมรัน `node --env-file=.env.local scripts/init-bank-transfer.mjs` แล้วกรอกชื่อธนาคารและเลขบัญชีคู่กันใน **ตั้งค่า QR รับเงิน** ลูกค้าเลือก **สแกนไม่ได้? โอนเลขบัญชี** เพื่อดูและคัดลอกได้

## พื้นที่จัดเก็บ 10 GB

ก่อนอัปเดตฐานข้อมูลเดิม รัน `node --env-file=.env.local scripts/storage-schema.mjs` (หรือ `npm run db:init` สำหรับการติดตั้งใหม่) เมนู **พื้นที่จัดเก็บ** นับโค้ด/โปรแกรม/บิลด์ที่ใช้งาน ฐานข้อมูลของแอป และไฟล์อัปโหลดร่วมกัน 10,000,000,000 bytes ไม่รวม OS, backup, log ภายนอกแอป, Git และบิลด์เก่าของเครื่องพัฒนา พื้นที่ฐานข้อมูลนอกเนื้อไฟล์ใช้ค่าประมาณจาก `information_schema.tables`; ควรกำหนด disk/container quota เพิ่มหากต้องบังคับพื้นที่ดิสก์จริงทั้งเครื่องอย่างเคร่งครัด

ทุกจุดอัปโหลดส่งชิ้นละ 1 MiB (เป็นขนาดการส่ง ไม่ใช่ข้อจำกัดขนาดไฟล์) และเก็บใน `storage_assets` / `storage_chunks` ข้อมูลเดิมยังอ่านได้ จองพื้นที่ทั้งไฟล์ด้วย transaction + `SELECT … FOR UPDATE` บนแถว `storage_quota` ก่อนรับชิ้นแรก จากนั้น transaction สั้นแต่ละชิ้นรองรับ retry ซ้ำ เมื่อบันทึกจริงจะตรวจสิทธิ์/ชนิดไฟล์ ผูกไฟล์กับรายการ และตรวจโควตาใน transaction เดียวกัน ห้ามถือ transaction ค้างตลอดการส่งไฟล์ผ่านเครือข่าย

ไฟล์ค้างที่ยังไม่ถูกบันทึกหมดอายุหลัง 24 ชั่วโมง; หน้าแอดมินตรวจทุก 30 วินาทีและการเริ่มอัปโหลดครั้งถัดไปจะคืนพื้นที่อัปโหลดค้างและไฟล์ที่ไม่ถูกอ้างอิง หลังลบไฟล์ InnoDB อาจเก็บพื้นที่ว่างไว้ใช้ซ้ำ จึงไม่รับประกันว่าไฟล์ฐานข้อมูลบนดิสก์จะเล็กลงทันที สำรองฐานข้อมูลต้องรวมตาราง storage ทั้งหมดด้วย วิดีโอรองรับ Range requests และสื่อใต้หน้าจอโหลดแบบ lazy / preload none

ทดสอบด้วย `scripts/test-storage.mjs` และ `scripts/test-storage-uploads.mjs` บนฐานข้อมูล local เท่านั้น กำหนด `TEST_BASE_URL`, `PLAYWRIGHT_MODULE`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE` ตามเครื่อง

## ตั้งราคาลานและวันเปิดจอง

- เมนู **ตั้งราคา** กำหนดราคาวันปกติและวันหยุด ค่าเริ่มต้นโหมดตามคนคือ 200 บาทต่อคืนสำหรับผู้ใหญ่คนเดียวต่อล็อก และ 150 บาทต่อผู้ใหญ่ต่อคืนสำหรับล็อกที่มีผู้ใหญ่ตั้งแต่สองคนขึ้นไป ระบบกระจายผู้ใหญ่ตามจำนวนล็อกเพื่อคิดราคา เมื่อมีผู้ใหญ่แต่จองมากกว่าจำนวนผู้ใหญ่ ล็อกที่เหลือคิดราคาเท่าล็อกผู้ใหญ่คนเดียว
- เมนู **ปฏิทินเปิด–ปิดและฤดูกาล** ใช้ปิดรับจอง เพิ่มวันหยุดพิเศษ หรือตั้งราคาช่วง Low Season และ High Season ตามวันที่ ระบบตรวจวันปิดก่อน จากนั้นใช้ราคาช่วงวันที่ วันหยุดพิเศษที่กำหนดราคาไว้ และราคาตามวันตามลำดับ เมื่อไม่มีราคาตรงเงื่อนไขจะใช้ราคาพื้นฐานหรือราคาวันหยุดสำหรับเสาร์–อาทิตย์
- ในแท็บ **เต็นท์** ของเมนู **อุปกรณ์ให้เช่า** แอดมินกรอกส่วนลดต่อผู้ใหญ่ต่อคืนและจำนวนผู้ใหญ่สูงสุดของแต่ละรุ่น แล้วเลือกเต็นท์ที่จะใช้ค่านี้ในหน้าต่างยืนยัน หรือแก้ไขทีละรุ่นในรายการเต็นท์
- เมื่อจองลานพร้อมเช่าเต็นท์ ระบบใช้สิทธิ์ตามค่าของรุ่นที่เช่า จำกัดส่วนลดตามค่าเช่าของรุ่นนั้น และใช้สิทธิ์ได้รวมตามจำนวนผู้ใหญ่จริง ใส่ 0 หรือเว้นว่างในฟอร์มแก้ไขรุ่นเพื่อปิดส่วนลดรุ่นนั้น

## Check-out ในแอดมิน

ฐานข้อมูลเดิมให้รัน `npm run db:init -- --checkout-only` ก่อนเปิดเว็บเวอร์ชันนี้

1. ไปที่ **ตั้งค่า Check-out** เพื่อปรับหน่วยไฟฟรีต่อคน ค่าไฟต่อหน่วย และเลขพร้อมเพย์ของแคมป์ ค่าเริ่มต้นคือ 1 หน่วยฟรีต่อคนและ 10 บาทต่อหน่วย
2. ในเมนู **Check-out** เปิดรายการจองที่ยืนยันแล้ว กรอกจำนวนหน่วยไฟ ค่าของชำรุด หรือค่าใช้จ่ายอื่น ๆ แล้วบันทึกยอด
3. ให้ลูกค้าสแกน QR สำหรับยอดที่ต้องชำระเพิ่ม เมื่อแอดมินตรวจสอบว่าได้รับเงินแล้วจึงกดยืนยัน Check-out

ระบบหักหน่วยฟรี (หน่วยฟรีต่อคน × ผู้เข้าพักทั้งหมด ÷ จำนวนล็อก) ก่อนคิดค่าไฟ และคิดเฉพาะหน่วยส่วนเกิน รายการที่ไม่มีล็อกใช้ตัวหาร 1 รายการที่บันทึกอัตราค่าไฟแล้วใช้สูตรที่บันทึกไว้กับรายการนั้น

## การจองและข้อมูลเริ่มต้น

หน้าตรวจสอบการจองแสดงชื่อ เบอร์ วันที่ รายการ ราคา ส่วนลด สถานะ จำนวนครั้ง และประวัติการเลื่อน ผู้จองเปลี่ยนได้เฉพาะวันที่และล็อกลาน โดยคงจำนวนคืน จำนวนล็อก ชื่อ เบอร์ จำนวนคน ห้อง อุปกรณ์ ราคา ส่วนลด และสิทธิ์เดิมไว้ อุปกรณ์ที่ผูกกับล็อกย้ายตามไปอัตโนมัติ ส่งสลิปแล้วเลื่อนได้แม้แอดมินยังไม่ยืนยัน รวมถึงรายการที่ยืนยันแล้วและยังไม่ Check-out ไม่มีปุ่มยกเลิกในหน้าตรวจสอบ

ก่อนยืนยัน ระบบตรวจวันเปิดรับจอง ล็อกว่าง และสต๊อกห้อง/อุปกรณ์/เต็นท์ทุกคืน โดยไม่นับการจองเดิม แล้วตรวจซ้ำภายใน transaction ก่อนบันทึก หากไม่พอแจ้งรายการและจำนวนคงเหลือ ไม่หักสิทธิ์และไม่เปลี่ยนการจองเดิม บันทึกสำเร็จใช้รหัสเดิมและนับ 1 ครั้ง การส่งซ้ำคำขอเดิมไม่นับซ้ำ สถานะตรวจสลิปคงเดิม แอดมินตรวจสลิปและยืนยันเอง

ฐานข้อมูลเดิมรัน `node --env-file=.env.local scripts/init-reschedule-history.mjs` ก่อนเปิดเวอร์ชันนี้ ทดสอบด้วย `node --env-file=.env.local scripts/test-restricted-reschedule.mjs` (local พอร์ต 3001) ประวัติใหม่เก็บวันและรายการก่อน–หลัง พร้อมเวลาที่เลื่อน ดูได้ทั้งลูกค้าและรายละเอียดจองแอดมิน เอาหน้า เมนู และการจัดการส่วนต่างเก่าออกแล้ว โดยเก็บข้อมูลประวัติส่วนต่างเดิมในฐานข้อมูลไว้ ไม่มีการสร้างส่วนต่างใหม่จากการเลื่อน

- ลูกค้าเลือกเหมาลานได้เมื่อไม่มีการจองที่ใช้งานอยู่ในทุกคืนที่เลือก คิดราคาตามจำนวนผู้เข้าพักรวมและวันของแต่ละคืน ในเมนู **ตั้งราคา** แอดมินเพิ่มหรือลบกลุ่ม แก้จำนวนคนสูงสุด ราคาจันทร์–พฤหัสบดี ราคาศุกร์–อาทิตย์ และหน่วยไฟฟรีของแต่ละกลุ่มได้ ค่าเริ่มต้นคือ 4,000 / 8,000 บาทและไฟฟรี 20 หน่วยสำหรับ 1–15 คน หรือ 7,000 / 14,000 บาทและไฟฟรี 50 หน่วยสำหรับ 16–60 คน ใช้ `npm run db:init -- --pricing-only` เพื่อเพิ่มรายการและช่องตั้งราคาเหมาลานในฐานข้อมูลเดิม

- Zone A มี A01–A10 ตามแบบ ราคาโหมดตามล็อกเริ่มต้น 500 บาทต่อล็อกต่อคืน โหมดตามคนคิดเฉพาะผู้ใหญ่ เด็กอายุไม่เกิน 13 ปีและผู้สูงอายุ 65 ปีขึ้นไปเข้าพักฟรี
- ราคาเช่า Snow Peak 600 บาทต่อคืน จำนวน 3 ชิ้นเป็นตัวอย่าง โซน B–D และ Trunkbox ยังไม่มีรายการเริ่มต้น แอดมินเพิ่มรายการ ตั้งราคา แก้สต็อก และเปิดหรือปิดรับจองได้
- เมื่อส่งคำขอ ระบบกันลานและสต็อกทันที แอดมินตรวจสลิป ยืนยันหรือยกเลิกได้ การยกเลิกคืนสต็อกทันที ผู้จองใช้รหัสและเบอร์โทรตรวจสถานะที่ `/booking` และเลื่อนตามเงื่อนไขด้านบน
- รุ่นนี้ใช้การยืนยันโดยแอดมิน และยังไม่เชื่อมระบบรับชำระเงินออนไลน์

## ทดสอบโหลดบนเครื่อง

เปิด production build ด้วย `npm run build -- --webpack` และ `npm start -- --hostname 127.0.0.1` จากนั้นเปิดอีกเทอร์มินัลแล้วรัน

```powershell
node --env-file=.env.local scripts/load-local.mjs
```

สคริปต์ทดสอบ 1,000 คำขอเช็กว่างพร้อมกัน และสองชุดอย่างละ 200 คำขอที่แข่งกันจองล็อกเดียวหรือเช่าอุปกรณ์ที่มีสามชิ้น รวมถึงการส่งซ้ำด้วยรหัสคำขอเดิม สคริปต์ใช้รายการชั่วคราวในฐานข้อมูลทดสอบแล้วล้างเฉพาะข้อมูลของรอบนั้น

ระบบใช้ InnoDB และล็อกแต่ละรายการตามลำดับรหัสระหว่างตรวจสต็อกและเขียนการจอง ราคาเก็บ ณ เวลาจอง สต็อกแยกตามคืนและไม่นับคืนวันเช็กเอาต์ การทดสอบบนเครื่องไม่ใช่ค่ารับประกันสำหรับ shared hosting

ก่อนเปิดใช้งานจริง ให้ตั้งฐานข้อมูลจริงและค่าลับผ่าน environment ของ Plesk ตั้ง cookie เป็น HTTPS เปลี่ยนรหัสแอดมินและ secret ตรวจข้อมูลจริงของทุกโซน และตั้งการจำกัดอัตราคำขอสำหรับการจองและการเข้าสู่ระบบ จากนั้นทดสอบโหลดบนสภาพแวดล้อมปลายทางและตรวจเวลาตอบสนอง การจำกัด CPU/RAM และจำนวน connection ของฐานข้อมูล
